# Fixed research operator verification source

This directory contains a reviewed, inactive operator proposal. It is not an executed API result or a live route/photo/phone acceptance record. Normal package/build configuration and public API mounts are unchanged.

## Scope and guards

One fresh, explicitly approved job may make at most two Google attempts. The second is available only to the current adapter's completed, genuine search/citation path for its existing URL Context readback. There are no GraphHopper or native calls. A durable claim and each provider reservation happen before IO; race/rebuild/replay cannot create another paid attempt.

The fixed public scenario and body digest are source constants. Source/input/approval/key/origin/expiry bindings are immutable. A fresh two-to-ten-minute binding is required; existing entitlements and cumulative ceilings are not renewed or reset. Literal baseline and prior-phase predicates in the SQL/generator are code preconditions, not a report of current database state.

The worker requires explicit production context, private activation flags off, strict existing TLS/role checks, active key/owner and enabled RLS/invoker/permission/accounting guards. It runs the exact research factory and final-envelope validator. Strict completed status, correlated calls/results, successful source reads and valid citations remain necessary.

## Explicit selection and later execution

Review the pinned source, SQL, generator, worker, configuration and fixed input digest. `prepareProtocolVerification.mjs` generates an insert-only proposal and public binding overrides; it does not execute them. `protocolVerificationSetup.sql` is additive setup source and does not create an approval or permit its own execution.

`vercel.protocol-verification.proposal.json` is a separate configuration requiring deliberate selection for one approved operator action. It never replaces default `backend/vercel.json` or installs a permanent build hook. Publication alone grants no deployment, database, provider or native operation. Any real execution needs fresh, separately reviewed authorization and bindings; never export secrets or commit generated metadata/requests.

## Results and limits

Only closed, bounded status/HTTP/count/token/validation fields may be recorded. Source URLs, text, raw provider bodies, function names/arguments/IDs, signatures, tokens and credentials remain excluded. The observer is frozen and cannot change validation. Typed result finishing preserves job identity and previous charges; revocation and expiry cannot reset or replay work.

The coordinator reports 135 credential-free fixture checks and eleven disposable PostgreSQL checks passing, zero failures/skips, plus manual SQL/worker/protocol review. These are synthetic/local checks, not real provider proof. Actual research, routing, Commons photographs and physical-phone persistence remain unproven. No real API execution is asserted by this source checkpoint.
